# 校园消防疏散 VR：手绘风格 UI 美术需求书

用途：可直接转发给画师。本文件说明“画什么、怎么分层、交什么文件”。画师不需要会 Unity、编程、交互配置、三维建模或动画。

本文尺寸是本次方案的建议出图尺寸，不是现有工程的硬性尺寸，也不是 VR 中的实际物理大小。程序接入时会调整显示大小和位置。暂不增加设置、选关、背包、商店、排行榜等新功能。

## 1. 项目与目标

这是校园火灾疏散 VR 训练。美术方向参考附带图片中的手绘设备、纸条、仪表和实体按钮：设备有厚度，轮廓略不规则，材质哑光，能看出手绘痕迹，文字与操作重点清楚。

主菜单设计为“校园消防值班室中的训练操作台”。训练中的 UI 使用同一套设备外壳、纸张、标签和图标语言。画师负责视觉；程序负责把图片放进三维场景、显示文字、更新数值、处理点击和动画。

### 参考图要借鉴的内容

- 厚实设备外壳、略不规则深色轮廓、手绘材质和纸张标牌。
- 有主次的局部灯光、能明确识别的实体按钮和指示灯。
- 物件旁边的短说明卡片。
- 参考图中的桌面、设备、房间是三维场景；不能只交一张桌面透视插画就当作可操作界面。

### 建议视觉基调

| 用途 | 建议颜色 | 要求 |
|---|---|---|
| 纸张、设备主体 | 米白 #E7DDC8 | 大面积文字区域尽量干净 |
| 墙面、次要设备 | 灰蓝 #526376 | 降低背景存在感 |
| 文字、轮廓 | 深墨色 #24282B | 笔触略有变化，文字区不做花纹 |
| 主要操作 | 暖黄 #E7AE45 | 开始、当前选中等视觉重点 |
| 完成、就绪 | 柔绿 #77A786 | 同时配合勾号或状态文字 |
| 危险、失败 | 警示红 #C95449 | 同时配合警告图形或状态文字 |
| 毛巾防护 | 清晰蓝 #5396BB | 与健康/危险状态容易区分 |

允许画师微调色值，但所有界面保持一致。风格专业、亲切、略旧；避免恐怖血腥、密集装饰、镜面科幻、大面积透明玻璃面板。

## 2. 工作分工：画师做什么，程序做什么

| 画师交付 | 程序负责，不需要画师操作 |
|---|---|
| 界面整体效果图、留白布局和分层源文件 | 导入 Unity、调整 VR 中的位置和大小 |
| 正视、平整、透明背景的底板、边框、按钮和图标 | 点击区域、射线、碰撞、按钮功能 |
| 按钮四种外观状态 | 指向、按下、回弹、震动、音效和亮灯 |
| 手柄示意图的静态零件 | 按键闪烁、摇杆移动、教学示范动画 |
| 操作台的概念图与正面/侧面设计参考 | 根据可用模型和设计搭建三维操作台 |
| 地图外框、纸张和地图图形语言 | 真实地图内容、定位、楼层切换和动态标记 |

三维模型不在本次画师默认交付范围内。纸张展开、按钮按下、仪表变化也不需要画师制作动画文件。

## 3. 最重要的区别：效果图和能用的素材要分别交

### A. 效果图：让人看懂最终样子

- 每张建议 2560×1440 像素，横向，PNG 或 JPG。
- 可以有透视、灯光、阴影、文字和示范数值。
- 用于确认设计，不直接作为整张游戏界面使用。
- 画师可用 2D 绘画画出房间和操作台，不要求三维渲染。
- 效果图里展示的按钮、提示卡、底板，必须能在分层文件中找到对应独立部分。

### B. 独立素材：实际放进游戏

- 正面平视、平整绘制，不加镜头透视，不把按钮画成斜的。
- 透明背景 PNG；每件东西分别导出。
- 阴影如需跨出物件轮廓，独立一层，不能带整块房间背景。
- 文字、数字、进度和状态符号与底板分开。
- 不要把所有元素压成一张“最终 UI 大图”后只交这一张。

举例：一张写着“开始训练”的黄色按钮，最终应拆成“黄色按钮底图 PNG”和“文字图层”；按钮底图本身不含文字，Unity 显示文字。

## 4. 全部需要设计的界面

每一项都交有示范文字的效果图；底板与装饰另按第 5 节导出。下列文案用于占位和布局，最终正式文字由程序写入。

### 4.1 主菜单：消防训练操作台

画面：玩家站在值班室桌前，中央训练终端，左侧任务夹板，右侧台灯。设备用米白和灰蓝，黄色开始按钮最显眼，退出按钮次要。

必有：

- 标题“消防疏散训练 / Fire Evacuation Training”。
- “开始 / Start”和“退出 / Exit”两个功能入口。画面主按钮可写“开始训练”。
- 操作说明的留白位置：“用手柄射线指向选项，按下扳机确认。”英文另留一行。
- 终端屏幕、设备外壳、开始按钮、退出按钮、指示灯独立设计。
- 夹板上可展示训练简介；这部分是展示内容，不额外增加可点击功能。

交付：一张主视角效果图；操作台/终端的正面、侧面结构草图；平整无字的终端面板、按钮等素材。台灯、桌子、墙面只需在概念图里表达，不要求把整个房间拆成贴图，也不要求画师制作模型。

### 4.2 暂停菜单

样子：一块简洁设备板或夹板，面对玩家展开；无需把主菜单桌子搬到玩家面前。

标题“已暂停 / Paused”。预留现有继续、重开、返回等操作的三行按钮布局；示范文案可用“继续训练 / Resume”“重新开始 / Restart”“返回主菜单 / Main Menu”。实际接入以工程已有按钮绑定为准，画师不要把文字焊死在图里。

按钮之间清楚分开，继续训练为主要按钮。交一张效果图及无字底板。按钮复用公共按钮素材。

### 4.3 成功和失败结算首页

样子：训练报告单或考核夹板。成功和失败使用相同结构，以标题、图标、印章和少量颜色区分。

成功示范：“成功撤离 / Evacuation successful”。失败示范：“演练失败 / Evacuation incomplete”。

共同预留：

- 结果说明/所在位置；失败时可能增加结束时任务，不能只留一行。
- 正式演练用时，示范数字“03:25”。
- 剩余血量，示范数字“68 / 100”和一条可变化的状态条。
- 三个入口：“查看明细 / View details”“重新开始 / Restart”“返回主菜单 / Main menu”。

交成功、失败两张效果图，共用一张无字报告底板；成功勾号/印章和失败警告/印章分别导出。印章可仅含图形；有文字时文字必须独立。

不要新增星级、排行榜、总评分等当前不存在的数据。

### 4.4 结算明细页

当前有四类明细，全部使用同一套报告页模板：

1. 任务完成情况：任务清单、完成状态，以及可选轮椅救援情况。
2. 血量与受伤：初始/剩余血量、累计损失、时间消耗、烟雾伤害等。
3. 毛巾防护：是否拾取、是否打湿、是否遮住口鼻、防护时长等。
4. 路线与改道：经过楼层、A 楼梯障碍、B 楼梯到达、操场出口、集合点等。

预留：顶部标题、页码“1 / 4”、正文左右两栏（左中文，右英文）、底部“上一页 / Previous”“返回结算 / Back to summary”“下一页 / Next”。

交一张正文较多的代表性效果图，另用草图展示四页内容均能放入。同一底板复用，不需要把四页每段文字画成图片。

### 4.5 课程说明与阶段提示

样子：纸张说明卡或教室告示板。

需要两种版式：大阅读卡、短提示条。大卡留标题、双语正文、操作示范区域、底部双语说明和阅读进度线。短条留标题与一到两段简短提示。

大卡示范：“火灾疏散知识 / Fire safety”，正文可用几行示范文字；短条示范：“前往教室出口 / Find the classroom exit”。所有文字可编辑。

大卡效果图、短条效果图各一张；示范区域保持可独立放置，不把手柄或手绘人物固定印在底板中。

### 4.6 操作教学

沿用课程卡风格，额外设计一套静态手柄图解。

内容包含：佩戴/观察、移动或传送、指向与扳机确认、抓取与松开、推门/开窗、地图 X 键、任务 Y 键、暂停操作等说明位置。

画师不需要决定“哪个按键负责哪个动作”，也不要根据别的游戏自创操作。手柄外形以本项目使用的 Quest 3 控制器为参考；最终动作和按键对应由程序核对后填写。

需要交：

- 左、右手柄各一张干净示意图。
- 摇杆帽、扳机高亮区域、握持按键高亮区域、按键高亮圈独立图层。
- A、B、X、Y 按键位置清楚，显示字符用独立文字层。
- 推动箭头、转动弧线、指向射线、正确勾号、错误叉号独立图层或复用图标。
- 一张含手柄示范的教学效果图。

不需要画动画帧序列，不需要制作 GIF。程序移动这些零件并控制闪烁。

### 4.7 任务面板

样子：夹板任务单。

要展示两种状态：

- 收起：小标签，留“Y 任务详情 / Tasks”的文字位置。
- 展开：标题、当前任务、任务说明和状态图形。按长任务预留多行双语空间。

四种任务状态：未触发、当前进行中、已完成、未完成。用图形和颜色共同表达，不要只靠颜色。

示范任务可使用“寻找毛巾”“浸湿毛巾并下到三楼”“遇阻后改走 B 楼梯”“打开操场出口”；可选任务为轮椅救援。画师只排版，不更改流程。

另设计“新任务”和“任务完成”的通知条效果；通知条底板可复用，状态图标分开。

### 4.8 地图面板

样子：纸质楼层疏散图，有清楚边框、图例和方向。

要展示收起、展开两种状态；收起入口留“X 小地图 / Map”，展开留楼层文字、地图主体、当前位置和方向标记的位置。

画师这轮交：无字地图纸张/外框、地图入口标签、方向箭头、位置点、目标点、楼梯/出口/避难区等图标，以及地图风格示意。

重要：真实房间、走廊、楼梯与出口的位置必须与 Unity 场景吻合，不能凭想象绘制可用路线。本轮默认继续由程序绘制地图内容；如以后需要手绘地图底图，再由程序提供准确平面底稿后描绘。玩家位置、楼层数字、房号、动态路线绝不画死在底图里。

### 4.9 常驻状态 HUD

样子：紧凑、易读的小型仪表，避免大装饰挡住视线。这轮做视觉样式，不指定改成腕表，也不更改现有控制方式。

必须分开：设备外框、空槽、满格填充、图标、危险提示装饰和文字位置。

演示健康、警戒、危险、毛巾防护四种状态。程序会控制填充长度、颜色与闪烁。条形填充从左到右增长，画师只交完整满格素材；不要为每个百分比重画。

数值和时间均由程序显示。原有血量随时间消耗的机制不要求画师重新设计。

### 4.10 普通物件提示与任务通知

样子：参考图那种米白底、深色手绘边框的小卡片。背后的设备、毛巾、水龙头不画进卡片里。

需要短卡和较长通知条两种尺寸。示范内容：“拿起毛巾”“打开水龙头”“毛巾已湿，持续握持并遮住口鼻”“任务完成”。英文另留空间。

卡片有足够内边距，边角可有轻微不规则；不要做夸张锯齿、强倾斜文字或大面积贴纸遮挡正文。

### 4.11 危险警告与救援通知

设计一套高优先级警告卡，黄/红强调边框、警告图形与留白正文区。

示范内容包括：离开烟雾区、火灾时勿用电梯、勿跳窗逃生，以及先送轮椅同学到二楼避难区再使用楼梯。

救援普通通知可复用普通通知卡，配轮椅或避难区图标；救援危险提示复用警告卡。交一张短警告效果、一张最长双语救援警告效果，确保换行后不挤满边框。

危险卡不做全屏血迹、满屏闪烁、透明度很低的文字底板。动画由程序处理。

### 图标清单

每个图标独立导出，透明背景，图形尽量简洁。建议文件名：

- 功能：icon_start、icon_resume、icon_restart、icon_home、icon_exit、icon_details、icon_previous、icon_next、icon_map、icon_tasks。
- 状态：icon_check、icon_cross、icon_pending、icon_active、icon_warning、icon_health、icon_clock、icon_protection。
- 训练物件/地点：icon_towel、icon_water、icon_smoke、icon_stairs、icon_elevator、icon_no_elevator、icon_no_jump、icon_safe_exit、icon_wheelchair、icon_refuge。
- 地图标记：icon_player_arrow、icon_target、icon_north。

任务完成可复用 icon_check；失败可复用 icon_cross 或 icon_warning；不用为同一图形改个用途就重复画一份。

这些是游戏内风格化提示图标；如果需要制作建筑中真实的法定安全标志，将另提供适用规范和标准原稿，不要求画师自行设计规范标志。

## 6. 每个按钮必须画的四种状态

“指向”指玩家的手柄射线停在按钮上；画师只需画这时的外观。

| 状态后缀 | 玩家看到什么 | 绘制要求 |
|---|---|---|
| normal | 没有指向时 | 标准颜色和厚度 |
| hover | 射线指向时 | 边缘/颜色明显变化，仍能读清字 |
| pressed | 扳机按下时 | 看起来稍微压低，阴影减小；动画由程序做 |
| disabled | 暂时不能操作时 | 降低饱和度/对比，轮廓保留 |

例如：button_primary_normal.png、button_primary_hover.png、button_primary_pressed.png、button_primary_disabled.png。

同组四张：画布尺寸一样，按钮中心一样，透明边距一样；禁止导出时自动裁切导致跳动。文字由程序叠加，不烘焙在任一状态里。按钮可点击范围由程序配置，装饰突出部分不等于点击区域。

## 7. 源文件图层与文字要求

画师使用自己熟悉的绘画软件即可，不要求学习新软件。交原生可编辑文件；能导出分层 PSD 时附一份 PSD；不能导出 PSD 时，原生文件加完整独立 PNG 也可以。

建议图层组：

```text
00_背景参考（仅效果图，独立可隐藏）
01_设备或纸张底板
02_轮廓与装饰
03_独立阴影
04_按钮_normal
05_按钮_hover
06_按钮_pressed
07_按钮_disabled
08_图标
09_中文文字（可编辑，单独一组）
10_英文文字（可编辑，单独一组）
11_示范数字与动态状态（可隐藏，不进底图）
12_留白和对齐说明（不导出）
```

- 效果图要带文字，以便审核排版；可用图片素材不带动态文字。
- 标题允许有少量手写气质，正文使用清楚的中文黑体或同类字体，避免正文全手写。
- 中文为主，英文略小，但需要独立行距；中英都用高对比颜色。
- 不随意缩小字体塞长句；长内容用更大的留白区或合理换行。
- 背景纹理不能穿过主要文字区；纸张中间平整，边缘可有折角和磨损。
- 记录使用的字体名称与来源；字体文件仅在授权允许时附带。可另交字体说明，不要求画师处理 Unity 字库。
- 动态文字包括任务、房号、楼层、数值、页码、结果、提示、按钮文案，均保留编辑能力。

## 8. PNG 导出要求：不懂软件设置时照此说明交付

1. 文件格式：PNG，支持透明的 RGBA，8 位/通道，普通 sRGB；无需 CMYK、印刷出血、300 DPI 印刷设置。
2. 背景透明指“物件外面没有背景”。纸张内部保持不透明或足够实，不能整张纸半透明。不要把棋盘格画进图片。
3. 每张图检查没有白色/黑色矩形底，没有意外杂点；边缘放在深背景和浅背景上看都干净。
4. 同一组按钮/叠加零件不要自动裁边；保持同尺寸、同中心、同位置。
5. 建议在 1024 像素宽底板边缘预留约 32～48 像素透明安全边距；所有状态一致，具体范围在源文件里标明。
6. 阴影、折角、夹子等不能盖住文字留白区。大底板边角需要保持形状，方便程序拉伸边框而不拉坏四角；画师只需标出“中间可伸缩、四角保持”的区域，不需要操作 Unity 切片工具。
7. 除效果图以外，不加拍摄透视、房间光影、景深、镜头模糊、水印或额外署名覆盖。
8. 效果图如果使用示范数据，请在说明中标注“示范值”；可用 PNG 不含这些数据。
9. 文件名用英文、小写、下划线；避免“最终最终修改2.png”。同一版整体放进一个版本文件夹。
10. 不需要交 Unity 工程、Prefab、脚本、FBX、视频或动画序列。画师若已有可用模型可另提供，但不是本次必须项。

## 9. 按顺序交稿，先确认样式再全面绘制

### 第一轮：风格确认

交：主菜单效果草图、一个纸张面板、一个主要按钮的四状态，以及几枚图标。先确认设备、线条、纸张、颜色和文字是否协调。此时可以先交草图，不要求一次做完全部精稿。

### 第二轮：第一批可接入素材

交：主菜单、暂停、成功/失败结算首页和明细模板；公共按钮、指示灯、成功/失败图标；对应无字 PNG 和分层源文件。接入后看实际阅读效果和布局，再调整后续界面。

### 第三轮：训练内 UI

交：课程卡、手柄示范零件、任务面板、地图外框、状态 HUD、普通提示、危险警告、救援通知；对应效果图、PNG 和源文件。

不要仅交效果图就视为完成；第二、三轮必须同时交可用的独立素材。
